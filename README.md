### Вопрос №1.01. Проверка пустой ссылки через функцию ЗначениеЗаполнено()
* **Суть платформенного механизма:** В платформе 1С пустая ссылка (например, `Справочники.Номенклатура.ПустаяСсылка()`) — это не `Неопределено` и не `Null`. Это полноценное валидное значение ссылочного типа, состоящее из нулевого уникального идентификатора (00000000-0000-0000-0000-000000000000). Системная функция `ЗначениеЗаполнено()` спроектирована так, что она распознает пустую ссылку любого типа и возвращает для неё `Ложь`.
* **Что проверяем на практике:** Проверяем пустую ссылку справочника с помощью `ЗначениеЗаполнено()`, а также сравниваем её с `Неопределено`, чтобы зафиксировать разницу в поведении системы.

### Вопрос №1.02. Поведение значений NULL при логических операциях сравнения в запросах
* **Суть платформенного механизма:** В языке запросов 1С:Предприятия значение `NULL` подчиняется правилам трехзначной логики SQL (истинного отсутствия данных). Любое прямое сравнение значения `NULL` с помощью стандартных математических операторов (`=`, `<>`, `<`, `>`), даже с самим собой (`NULL = NULL`), принципиально возвращает результат `Ложь` (точнее, `Unknown`, который трактуется как `Ложь`). Для корректного определения пустого SQL-поля (например, при левом соединении) платформа требует использовать специализированный унарный оператор `ЕСТЬ NULL`.
* **Что проверяем на практике:** Выполняем SQL-запрос к справочнику, вычисляя выражения `NULL = NULL` и `NULL ЕСТЬ NULL` внутри конструкции `ВЫБОР`. Доказываем разницу в логике СУБД.


### Вопрос №1.03. Особенности неявного приведения типов при сложении в языке BSL
* **Суть платформенного механизма:** В программном коде 1С тип результирующего выражения при использовании оператора сложения `+` жестко определяется типом **первого (левого)** операнда. Если левый операнд имеет тип `Строка`, платформа выполняет конкатенацию, приводя правый операнд к строке. Если левый операнд имеет тип `Число`, платформа пытается выполнить математическое сложение, принудительно преобразуя правый операнд к числу. Если правая строка содержит нецифровые символы, система генерирует неустранимое исключение времени выполнения (Runtime Error) «Преобразование значения к типу Число не может быть выполнено».
* **Что проверяем на практике:** Поочередно складываем строку с числом и число со строкой (включая невалидную текстовую строку), перехватывая системную ошибку типизации через блок `Попытка...Исключение`.
